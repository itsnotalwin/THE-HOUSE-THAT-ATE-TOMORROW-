# Visual verification

Capture the running game at desktop review sizes with the entire canvas visible. Inspect text wrapping, objective/prompt placement, focus visibility, native sprite edges, furniture depth, Here/Almost contrast, dialogue choices, notebook scrolling, and settings. Check both standard and large reading sizes before claiming both are verified.

Use PNG for screenshots and record the engine, browser, viewport, and source build alongside the captures. A console warning or fallback renderer should be documented according to its actual effect. Headless logic tests do not establish visual quality or audible output.

`SCREENSHOT.png` must come from the running implementation. Original concept references and earlier art/UI studies remain under `../art_references/` and `../art_staging/` and must not be presented as runtime evidence. The approved native world uses 384×216 nearest-filtered rendering; the UI is a separate higher-resolution layer.
